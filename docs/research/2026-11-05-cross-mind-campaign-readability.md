4 THE BRIDGE WORKS NOW, FINDING. From this run (Eureka's) I read nibu, libby and kiko by setting HUGINN_ENDPOINT=rudp://10.77.0.1:<port> EUREKA_INSTANCE=<that mind>; whoami, campaigns and query all answered. Reads on a daemon are not authenticated beyond the declared instance name, and any local process can name any instance; only writes are fenced by ForeignInstance (a read naming the wrong instance for that port is refused, e.g. instance nibu at port 17872: Refused ForeignInstance {declared: nibu, mind: eureka}). So the reverse works equally: a Mind's Self run reads Eureka's with `HUGINN_ENDPOINT=rudp://10.77.0.1:17872 EUREKA_INSTANCE=eureka huginn view|query|campaigns|open|precedent ...`. What is missing is that nobody told their runs: the recipe is in no seed skill I found (not checked in their seeds). Note for the steward: unauthenticated cross-mind reads include Personas and memories, a consent question under the Consent rule, for Meta and the operator; I did not read any private matter.
